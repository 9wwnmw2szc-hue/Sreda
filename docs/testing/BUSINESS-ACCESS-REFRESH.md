# Обновление доступа в открытом интерфейсе

## Исправление
После принятия приглашения из настроек `router.refresh()` сохранял состояние BusinessProvider.
Его прежний эффект загружал список только при смене аккаунта, поэтому новый бизнес мог не появиться в переключателе.

Теперь принятие приглашения вызывает обновление списка и выбор приглашённого бизнеса до перехода в Dashboard.
Список обновляется при возвращении во вкладку и каждые 30 секунд в видимой вкладке.
Сервер проверяет права на каждом запросе независимо от этого интервала.
Если доступ отозван, выбирается другой доступный бизнес; при отсутствии доступных бизнесов список пуст.
При ошибке проверки устаревшие бизнесы не показываются; в настройках есть кнопка повторной загрузки.
Поздний ответ предыдущего запроса не заменяет более свежий результат.
Панели участников и журнала пересоздаются при смене роли, чтобы не сохранять старые данные владельца.

## Проверка
Изменения проверяются lint, TypeScript, production build и CI, включая production HTTPS-сценарий из PR #5.
Серверный сценарий не исполняет клиентский JavaScript.
Попытка открыть отдельную локальную страницу проверки компонента в браузере 12 сентября 2026 завершилась `net::ERR_BLOCKED_BY_CLIENT`.
Браузерная проверка этого исправления остаётся открытой; тестовую страницу в поставку не включаем.

## Приёмка в браузере
1. Пользователь с собственным бизнесом принимает приглашение во второй: новый бизнес сразу появляется и выбирается.
2. Владелец меняет роль второго пользователя: при возвращении во вкладку второго пользователя роль обновляется.
3. После отзыва доступа второй пользователь перестаёт видеть бизнес; следующий API-запрос запрещён немедленно сервером.
4. При потере соединения доступны сообщение об ошибке и повторная загрузка списка.
5. Медленный старый ответ не возвращает отозванный бизнес поверх нового ответа.
6. Проверить мобильную ширину 390 px и клавиатурное управление.
