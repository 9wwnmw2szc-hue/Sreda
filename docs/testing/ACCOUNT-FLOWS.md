# Проверка аккаунтов и рабочих пространств

Проверено 12 сентября 2026 в GitHub Actions, run 34702192780, commit 038c10c22b7b6ac2188726841968bd663dac4b8f.
Production HTTPS-сценарий, обычные PostgreSQL-тесты, lint, build и typecheck завершились успешно.

## Цель и границы
Проверить production-сборку Next.js через HTTPS и настоящие HTTP-маршруты с PostgreSQL.
Это интеграционная проверка сервера, а не имитация браузера: она не исполняет клиентский JavaScript, не проверяет клики, фокус, localStorage и адаптив.

## Запуск
Требуются Node.js 22+, OpenSSL, установленный проект и локальный PostgreSQL 17.
У тестовой роли должно быть право CREATEDB. Используйте отдельную тестовую роль, не production-реквизиты.

```sh
npm ci
npm run build
TEST_DATABASE_URL=postgresql://biznesoty:ci-only-password@localhost:5432/biznesoty_test npm run test:http
```

Указанный пароль — пример для локального тестового PostgreSQL из CI, не рабочий секрет.
Runner допускает только loopback-адрес и исходную базу с `test` в имени.
Он создаёт новую базу `biznesoty_http_test_<случайный суффикс>` и применяет миграции дважды для проверки повторного запуска.
Тест не очищает исходную базу. В конце удаляется только созданная им база.
Секрет авторизации, пароли и сертификат HTTPS генерируются на запуск и не сохраняются в репозитории.
Проверка сертификата не выключается: клиент доверяет только временному тестовому сертификату.

## Автоматический сценарий
1. Анонимный запрос, несовпадение паролей, регистрация двух аккаунтов и атрибуты session cookies.
2. Страница нового пользователя с публичным ID; Dashboard направляет пользователя без бизнеса на создание/принятие приглашения.
3. Создание бизнеса в часовом поясе Калининграда, приглашение администратора и принятие пользователем без своего бизнеса.
4. Запрет администратору отозвать владельца, проверка CSRF, смена роли на оператора и ограничение доступа к подключениям.
5. Проверка реально зарегистрированного DELETE-маршрута и создание заявки.
6. Перезапуск процесса Next.js: сессия и заявка сохраняются в PostgreSQL.
7. Отзыв доступа: следующий запрос отклонён, старое приглашение не восстанавливает доступ; выход инвалидирует сессию, повторный вход работает.

В GitHub Actions сценарий выполняется после unit/service-тестов, lint, build и typecheck.
Наличие `test:http` не заменяет конкурентные PostgreSQL-тесты из обычного набора.

## Ручная браузерная проверка — ещё требуется
В отдельном согласованном окружении пройти ввод логина и пароля, ошибки формы, копирование публичного ID, принятие приглашения, появление бизнеса в переключателе без перезагрузки, смену роли и отзыв.
Особенно проверить обновление уже открытой вкладки второго администратора и отсутствие данных предыдущего бизнеса после переключения.
Проверить мобильную ширину 390 px, клавиатуру, сообщения об ошибках и повторное открытие страницы.
Текущий автоматический тест не является подтверждением этих сценариев.
