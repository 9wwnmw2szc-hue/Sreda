# Серверные заявки в Dashboard

В обычном режиме getLeads запрашивает GET /api/v1/businesses/{publicBusinessId}/leads
с cookie текущей сессии и cache: no-store. Ошибки API не подменяются пустым списком.
Демо-режим сохраняет mock-данные; production не может включить демонстрационную авторизацию.

Dashboard показывает три последние заявки по createdAt. Счётчик отражает новые среди этих трёх,
а не общее число новых заявок в бизнесе. API отдаёт до 100 последних записей, достаточных для этого блока.
Кнопка «Обновить заявки» повторно загружает данные Dashboard и показывает загрузку.
Обновление списка бизнесов существующим provider также запускает обновление данных выбранного бизнеса.
При смене бизнеса запоздалый ответ предыдущей загрузки игнорируется существующим cleanup эффекта.
Снимок не отображается при отсутствии доступного бизнеса или во время загрузки списка бизнесов.

Карточка заявки показывает имя, площадку, телефон при наличии, сообщение, статус и дату.
Реальные заявки не помечаются демонстрационными. Открытая карточка берёт свежую запись из текущего списка;
скрывается при смене бизнеса, загрузке, ошибке или исчезновении записи из последних трёх.
Данные выводятся текстом React, без HTML из сообщения клиента.

## Проверки
Добавлен интеграционный тест реального клиентского сервиса с транспортом к настоящему application handler и БД.
Проверены scoped URL, same-origin cookie/no-store, два бизнеса владельца, порядок/лимит,
обновление статуса, отказ другому пользователю и отсутствие сессии. Общий набор: 39 тестов,
34 локальных и 5 конкурентных только для PostgreSQL. Lint, build и typecheck — обязательные проверки.
CI дополнительно выполняет существующий HTTPS-проход production routes.

## Открытая приёмка
Браузерный доступ ранее заблокирован; новый responsive review не выполнен.
Нужен ручной проход на 1440/1280/900/390: список/пустота, длинное сообщение, телефон, обновление,
медленное переключение A → B, отзыв доступа при открытой карточке, ошибка API и повтор.
До такого прохода UI не считается визуально принятым.

Полная страница /leads пока заглушка: этот PR подключает только Dashboard и просмотр карточки.
Редактирование статуса из UI, полный список с фильтрами/пагинацией и реальная доставка из Telegram — следующие задачи.
Подключённые решения, публикации и billing здесь не становятся серверными автоматически.
Яндекс Cloud отложен пользователем; production не разворачивается.
