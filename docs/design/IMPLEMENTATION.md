# БизнеСоты: реализация утверждённого Dashboard

## Исходная точка

Проект продолжает Biznebiznesoty-transfer.zip из Cursor, исходная ветка cursor/sreda-stage1-foundation-04e7, commit 33008957e31d4135e4edfd519163df5f8c4ce93c. Next.js/React/TypeScript, маршруты, services и mock-слой сохранены. Новый GitHub-репозиторий: 9wwnmw2szc-hue/Biznesoty. Эта работа — frontend, не работающая интеграция с площадками.

Актуальный пользовательский референс: [sreda-approved-desktop-mobile.png](sreda-approved-desktop-mobile.png). Старый APPROVED-DESIGN-REFERENCE в public/assets/sreda/decor относится к предыдущему варианту. Не использовать его как текущий источник композиции.

## Что реализовано

- Graphite sidebar, светлая верхняя панель и operational-зона, тёплая деревянная поверхность.
- Четыре стеклянных 3D-модуля: зелёные заявки, розовые продажи, голубой автопостинг, жёлтая запись.
- Новые WebP в public/assets/sreda/v2. Это предварительно отрендеренные 3D-изображения с прозрачностью, а не WebGL-сцена.
- Подписи, статусы, цены, кнопки, поиск, переключатель бизнеса и модальные окна — настоящий HTML, не текст внутри картинки.
- Каталог/просмотр решения, просмотр заявки и поста, поиск по загруженным решениям и последним событиям, мобильное меню.
- Переключение mock-бизнесов обновляет весь snapshot. Старые данные не отображаются под новым бизнесом. Это исправление UI, не реализация серверной tenant-изоляции.
- Установленные решения и статусы вычисляются из данных. На мобильном не захардкожены два конкретных решения.
- Из ближайших постов исключены опубликованные и черновики. Даты demo фиксированы; реальный планировщик отсутствует.

## Геометрия сцены — обязательна для Cursor

Файл src/config/scene.ts — единственный источник координат. Полный frame 1536×1024. Видимая область 1536×850; frame сдвинут на -5% собственной высоты для удаления лишнего пространства сверху/снизу. Модули и подписи находятся внутри этого же frame. Не привязывать их к viewport, sidebar или всей странице.

| Модуль | X, % | Y стопы, % | Ширина кадра модуля, % | X подписи, % | Y подписи, % |
|---|---:|---:|---:|---:|---:|
| Заявки | 46.7 | 40.5 | 21 | 38 | 22 |
| Продажи | 66.4 | 40.5 | 20 | 77 | 22 |
| Автопостинг | 45.7 | 63 | 22 | 36.5 | 44 |
| Запись | 67.1 | 63 | 22 | 77 | 44 |

Для левых подписей X задаёт правый край карточки (translateX(-100%)): он расположен на 38% для заявок и 36.5% для автопостинга, непосредственно рядом с модулем. Это удерживает небольшой зазор при изменении ширины сцены.

Изображения имеют прозрачные поля, стопа привязана через translate(-50%, -88%). Не менять export/прозрачные поля без повторной настройки якоря. Задний ряд z=2, передний z=3, подписи z=10, фон z=0. ?debugScene=1 показывает якоря.

Платформа намеренно получила приподнятый задний ряд: это устраняет перекрытие символов передними модулями при сохранении тёплой 3D-концепции. Декоративная обстановка и логотип не являются пиксельной копией генеративного референса. Окончательное визуальное принятие остаётся за владельцем продукта.

## Адаптив

- 1360+ px: sidebar 224 px, правая колонка 260 px. С 1550 px — 244/280 px. Общий max-width 1920 px.
- 1100–1359 px: sidebar 200 px, правая колонка 224 px.
- 768–1099 px: верхняя мобильная шапка/меню, широкая сцена, служебные панели в две колонки под сценой.
- До 767 px: без платформы, карточки установленных решений, кнопка каталога, заявки, ближайший пост, далее подключения/тариф. Четыре пункта нижней навигации; учтён safe-area.

## Ограничения и следующий этап

Другие маршруты пока заглушки исходного этапа. Нет реальной регистрации, подключения Telegram/VK, оплаты, изменения данных или публикации. Не выдавать эти действия за готовые. Не внедрять backend и не переделывать текущую визуальную систему под видом продолжения этой задачи.

Для любого изменения композиции снова предоставить 1440/1280/900/390, lint/typecheck/build и визуальное сравнение. Не заменять ассеты CSS-кубами. Не раскладывать координаты по JSX/CSS. Не объединять данные разных бизнесов и не сохранять секреты на frontend.
