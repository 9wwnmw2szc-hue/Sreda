# Смена пароля из настроек

POST /api/v1/account/password принимает currentPassword, newPassword и passwordConfirmation.
Пользователь и текущая сессия определяются сервером. Переданные userId, sessionId и параметры отзыва игнорируются.
Нужны действующая сессия, совпадающий Origin, JSON до 4096 байт и подтверждение текущего пароля.
Лимит: 5 попыток на аккаунт за 10 минут. Пароли 10–128 символов, без обрезания, новый отличается от текущего.

Хеширование и проверка — better-auth/crypto. Транзакция блокирует строку пользователя, как восстановление доступа,
повторно проверяет наличие сессии, проверяет пароль, обновляет хеш, удаляет остальные существующие сессии
и записывает password_changed. Ошибка любого шага откатывает всё. Текущая сессия сохраняется.
Используется прикладная транзакция, потому что стандартный change-password в установленной Better Auth
обновляет пароль и пересоздаёт сессию отдельными операциями, а восстановление уже использует блокировку пользователя.
Резервные коды не меняются. Ответ содержит только ok, без внутренних ID и токенов; Cache-Control: no-store.
Миграция 013 расширяет список событий, не изменяя ранее применённую 012.

Форма очищает пароли после завершения запроса, блокирует повторную отправку, показывает ошибки и результат.
Демо-режим не показывает форму. PIN и вход по коду мессенджера остаются отдельными этапами.

## Проверка
Сервисные тесты: сохранение текущей и отзыв остальных сессий, изоляция другого аккаунта,
работоспособность резервного кода, отказ старого пароля, подтверждение и лимиты, откат при сбое аудита.
PostgreSQL: две одновременные смены не могут обе принять старый пароль.
HTTPS-тест вызывает настоящий production route и проверяет вход новым паролем и отзыв второй сессии.
Ручная приёмка формы с клавиатуры и на 390/900/1280/1440 остаётся открытой: локальный браузерный доступ заблокирован.

## Граница гарантии
Удаляются существующие на момент операции сессии. Параллельный вход, уже начавший проверку старого пароля
в auth-библиотеке, пока не связан общей версией учётных данных. Перед публичным запуском нужен единый механизм
инвалидации для входа, восстановления и смены пароля, с тестом такого пересечения.
Если потерян контроль над текущим устройством, следует использовать восстановление с другого устройства:
оно завершает все существующие сессии. Остальные вкладки того же браузера разделяют текущую cookie.
