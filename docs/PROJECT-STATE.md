# Среда — состояние проекта
Обновлено 12 сентября 2026. Точка входа для продолжения работы.

## Продукт и принятые решения
Готовые инструменты для малого бизнеса с общими данными Web, Telegram и VK.
Разработка полностью в ChatGPT. Визуальная основа — одобренная 3D-сцена Dashboard.
Регистрация: логин, пароль и повтор пароля. Email пользователю не нужен.
Вход по коду Telegram/VK появится после подключения бота и подтверждения личного получателя.
Пользователь и бизнес — отдельные сущности. Членство связывает их и задаёт роль.
Публичные usr_/biz_ ID используются в интерфейсе; внутренние UUID остаются на сервере.
ID не заменяет проверку доступа. ID остальных ресурсов (приглашений, заявок, журнала) — непривилегированные UUID, а не секреты.

## Реализация в этом наборе изменений
- Dashboard, каталог и мастер настройки с черновиками отдельно для каждого бизнеса.
- Better Auth username/password, хеширование паролей, серверные сессии, CSRF и ограничение попыток входа.
- PostgreSQL, миграции 001–011, создание и переключение бизнесов, серверная проверка членства.
- Приглашения по публичному ID, принятие, отзыв доступа, роли owner/admin/operator.
- Входящие приглашения доступны без собственного бизнеса на /business/new.
- Изменения участников и журнал действий сохраняются в одной транзакции; блокировка строки бизнеса упорядочивает конкурирующие изменения.
- API заявок: создание, список, статус, изоляция по бизнесу, дедупликация по каналу и ID события.
- Хранение токенов с AES-GCM, проверка Telegram getMe, удаление секрета при отключении.
- Один Telegram-бот не может одновременно принадлежать двум бизнесам.
- Внешним ответам API не передаются токены и внутренние ID пользователя/бизнеса.

## Границы готовности
- Проверка токена Telegram не запускает обработку сообщений. Webhook, сценарий бота и доставка кодов входа отсутствуют.
- VK пока только заготовка хранения; проверка сообщества и адаптер не реализованы.
- Dashboard и мастер не полностью переведены на реальные данные заявок и настройки решений.
- Нет платежей, production-инфраструктуры и проверки реальным владельцем бота.
- Ключ токенов пока производный от BETTER_AUTH_SECRET. Его смена требует отдельно спроектированной перешифровки; независимые ключи и ротация нужны до production.
- Реальный end-to-end сценарий с внешними каналами остаётся отдельным этапом.
